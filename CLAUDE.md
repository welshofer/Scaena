# CLAUDE.md — Scaena

Scaena is a presentation engine: **a timeline of states over one persistent scene graph**, rendered deterministically by one Rust core to the browser, the Mac, PDF, and video. Read `docs/MANIFESTO.md` for why, `docs/SPEC.md` for what, `docs/PLAN.md` for when. Decisions live in `docs/adr/`.

## Start here

1. `docs/PLAN.md` is the live task list. Work the lowest unchecked task in the current phase. Do not start the next phase before the current gate's exit criteria are met and logged in the gate log.
2. `just check` must be green before any commit (fmt, clippy with `-D warnings`, tests, schema validation).
3. Keep `docs/SPEC.md`, the JSON schemas, and the examples consistent with the code. If a code change forces a format change, the same PR updates the schema, the examples, the spec section, and bumps the format version. A change that takes anything away, or narrows what a value may be, also raises `OLDEST_FORMAT_VERSION` (or `OLDEST_THEME_FORMAT_VERSION`), or reads the older formats as they drew (`scaena_core::version`: a deck saved before 0.25 reads without its `shadow`s): every older format from the oldest on opens as the current one (SPEC §3.1).

## Invariants (violations are bugs, not style)

1. **Determinism.** `render(document, theme, state, t, viewport)` is pure. No wall clock, no unseeded randomness, no system fonts in the render path. (SPEC §13)
2. **Painters never shape text or lay out.** Glyph positions are final in the display list. (SPEC §6)
3. **Layout is per snapshot; frames only sample.** Never re-run layout inside the frame loop. (SPEC §5)
4. **Semantics over pixels.** Documents reference roles, slots, tokens, presets. Raw literals live only in `overrides` and are lint W300 elsewhere. (ADR-0005)
5. **Tracking semantics are in `scaena-core::tracking`** and nowhere else. `anim` never tracks. `layout` does.
6. **Nothing render-derived enters the CRDT.** Snapshots, layouts, display lists, lint results are recomputable. (SPEC §8.3)
7. **No server assumptions in v1.** Local-first; BYOK; keys never in bundles. (ADR-0006)
8. **PPTX/Keynote never touch the model or the engine. No HTML/CSS layout in the engine. No TextKit where a deck is drawn.** (MANIFESTO) The source pane's editor is chrome, as the browser's CodeMirror is (SPEC §9.3; Jay's call, 2026-10-11).
9. **Shader nodes have a CPU reference implementation first**, WGSL second, parity test third. No arbitrary shader source. (SPEC §3.8)
10. **Authority:** the logical document is the truth; `deck.json` is its canonical interchange form; the CRDT holds persistence authority while editing; `.scn` is an authoring projection. DSL round-trip is semantic (`compile(decompile(doc)) == doc`), never source-preserving. (SPEC §3.1, §4)

## Conventions

- CI (`.github/workflows/ci.yml`): a draft pull request gets the fast checks on Linux; one ready for review gets Linux in full (the painters on lavapipe, the WASM engine and its walks in Chromium), and macOS only where it touches an Apple path, each for its own reason: what paints (`scaena-paint`, `scaena-pixels`, `scaena-core`'s shaders, `tests/golden/`) runs the workspace's tests and the painters on Metal; what builds the apps (`scaena-ffi`, `apps/`, the shots script) runs the C ABI's tests, ScaenaKit, the Mac app's window, and the iPad job; `Cargo.lock` and the workflow run both, as the `apple` label does. A change elsewhere that Swift reads through the C ABI, and that a ScaenaKit test holds, should carry the label. The bench gate judges a cold bench (`render_cold`, `mcp_render`) with its group: by the median of its decks' changes, timed again as a group, regressing when that median is past the floor every time; a cold deck over its SPEC §15 budget fails alone (`scripts/bench_gate.py`).
- Rust 2024 edition, stable toolchain. `cargo clippy --all-targets -- -D warnings` is clean. `cargo fmt` (rustfmt.toml: 120 cols).
- Crates depend downward only: `cli`/`mcp`/`serve → ops → export/paint/engine/store → core → pixels`, `ops → narrato` and `ops → sources` behind `ops`' `narrato` feature, `cli → sources` (which depends on no crate of ours), `cli`/`mcp`/`ffi → objects → core` (ADR-0030), `wasm`/`ffi → session → ops`, and `generator → ops`, for the deck a narrative builds and nothing else, its module loaded apart from the editor's. `core` has no heavy dependencies, `pixels` none but `thiserror` and `libm`, and `fence` none at all, so each crate that builds a model's prompt may take it. An operation lives in `scaena-ops` and returns a typed result; the CLI and the MCP server only parse, call, and print or return it (ADR-0009).
- Stable sorts in the crates the browser's modules carry (core, engine, ops, session, store, wasm) go through `scaena_core::sort`: `slice::sort_by` compiles a whole sort for each call site, some 10 KB of WASM, and the editor's module is held to SPEC §15's 3 MB. `crates/scaena-wasm/tests/sorts.rs` holds them to it. A map or a set built from an iterator goes through `sort::map`, `sort::try_map`, or `sort::set`: `collect` into a `BTreeMap` sorts first, and compiles that sort for each type and caller (PLAN 2.91). The same test finds a `collect` typed as one.
- Errors: `thiserror` in libraries, `anyhow` only in `scaena-cli`. Unimplemented paths return `NotImplemented("… — PLAN x.y")`, never `todo!()`, so the CLI exits 3 with a pointer instead of panicking.
- A deck, theme, bundle file, or tool call the engine cannot serve is an error that says why, never a panic or a hang: in the browser either stops the editor's worker. `crates/scaena-session/tests/edits.rs` makes random edits to sources, decks, patches, and themes, and random calls to the assistant's tools, in `just check`, and lays out, lints, and draws the deepest deck validation allows on a worker thread's stack. A damaged font's glyphs are checked before a painter sees them, and a raster holds at most `scaena_paint::MAX_PIXELS` (PLAN 2.23–2.26). A picture whose pixels do not decode is drawn as its box left empty by every painter and export, and lint finds it, E107, with its file and why (`Backdrop::picture`).
- Every lint rule: a struct implementing `Rule` with a stable code from SPEC §7.5, plus fixtures under `tests/lint/<CODE>/trigger.deck.json` and `tests/lint/<CODE>/clean.deck.json`.
- Every change to layout/text/timeline/painters updates golden display lists in the same PR; the diff is reviewed, not regenerated blindly.
- New node types, properties, or state fields: change the typed model (`scaena-core::model`; the deck's skeleton is `scaena-core::document`) → `just bless` regenerates `docs/schema/*.json`, which nobody edits by hand (ADR-0007) → `docs/examples/*` → SPEC §3. Run `just schema` to validate.
- Commit messages: imperative, one line, optional body. Reference PLAN task ids (`PLAN 0.4`) and ADRs.

The CLI today: `scaena new | generate | validate | lint | inspect | diff | save | compile | decompile | theme --apply | theme --edit | theme --from-photo | patch | find | data | files | health | history | map | start | background | icons | export --format spine|pdf|png|svg|mp4|webm|prores` work, on a bundle directory or a `.scaena` zip. `new` makes a bundle as `deck_create` does, from a theme that ships, by name, or a theme file (PLAN 2.13): the CLI and the MCP server carry every theme the registry lists and every font each names, compressed, found at build in git or the sha256 cache `build_bundle_fonts.py --fetch --shipped` fills, never the network (`scaena-ops`' `shipped` feature, `build.rs`, PLAN T.0c). `start` starts a slide after a state's slide in one of the theme's layouts, as Add Slide does, and `background` sets a slide's background to one of the theme's shader presets or takes it away, listing those it may take when given neither (PLAN 3.30, 2.148; narrative FUNC-5). `validate` checks a bundle as it is on disk: both schemas, every reference to a file or theme name, every grid cell against the theme's grid in each format (PLAN 1.37), and each resolved state against its nodes' types (PLAN 1.2). A theme's grid lays out 1 to 1,000 columns and rows with room for each (`Grid::unfit`): past that it is E106 and an engine error naming the field, never a run out of memory; a video plays at most 24 hours, refused past it naming the hold or the beat's duration (lift-up 10-24b STAB-3). `save` subsets fonts and names files by their content without changing a frame (PLAN 1.4). Every write of a bundle is whole or none: each file goes to a partial beside it, synced, and is renamed into place, a save staging every file before any is renamed, so a crash or a full disk leaves the bundle as it was (`scaena_store::write_whole`, lift-up REL-3). A bundle that cannot be read or written says which file and why (`StoreError::Read` and `Write`, the io cause kept), and an operation's error joins each cause behind it (lift-up 10-24b USE-3). A `.scaena` zip is read within bounds, 10,000 files, 256 MB a file, and 1 GB in all, past which it is refused, naming the file (`scaena_store::UNZIPPED`, lift-up SEC-1). A link in a bundle's folder that leads out of it is neither read, written, nor walked, and a theme's font is taken only from under its folder (`StoreError::LinkedOut`, `create::font_in`). `compile` turns `.scn` into `deck.json`, validating it and showing each finding at its source line, and `decompile` writes any deck as canonical `.scn`; the round trip is exact (PLAN 1.5, SPEC §4); a value nested past 127 deep, as deep as `deck.json` may, is refused at its source line, and a compile that cannot read back what it made says why, never panics (lift-up STAB-1). Every node passes through the theme cascade (role → `style` → state → `overrides`, SPEC §3.6): `theme --apply` re-themes a bundle and reports the lint delta, refusing a theme that would leave the deck invalid unless `--force` (PLAN 1.35), and sets each text the theme would leave too faint to read where it stands in the theme's color that reads there, as its contrast error's fix does (`recolored`, PLAN 2.82; Jay's call, 2026-10-13), and fits each text it sets past its box or over another as lint's E100 or E101 fix fits it, what no fix reaches staying in the delta (`refitted`, dogfood pass 2); a text set larger than the body whose descenders alone reach the text under it is E101 with I405's step, found at it and set smaller until clear, never under half its size, so a re-theme refits it, a grown text kept growing under a smaller `maxSize` (after #564); `theme --edit` edits the theme the deck names by JSON Patch, refused as a re-theme is where the deck would not validate in it, the theme written canonically (PLAN 2.61, ADR-0016). `theme --from-photo IMAGE` makes such an edit from a photo the bundle holds. The accents take the photo's hues and the neutrals its lean, on the theme's own tones. Each color text is set in is kept where it reads on the surfaces (PLAN 2.94, `scaena_core::palette`). `theme --sheet THEME --out FILE` draws a theme's contact sheet, every layout started as Add Slide starts it, on one PNG by its sections, no bundle needed; each start's display-list digest is kept in `tests/golden/themes/<slug>.digests.json` to catch drift (PLAN T.0e). The shipped themes, Dusk, Daybreak, Ember, and Salon (Instrument Serif headlines over Inter, PLAN 2.102; it shipped as Gallery, and `gallery` still finds it, PLAN T.0d), share one vocabulary of layouts, slots, roles, and presets on one 12 × 12 grid, so a deck moves between them with no E102 (SPEC §3.6, PLAN 1.34). `inspect --resolved` shows each text node's look and its overrides (PLAN 1.6). A text role with `snap` sets its baselines, or its first cap height, on the theme's baseline grid, and lint W221 flags a snapping leading that is off it (PLAN 1.25). A placement's `inset` is a length as any is: a number, canvas units, a percentage, or a theme token (`space.N`), an unknown one an error that says so (`Theme::length`). `inspect --timeline` shows each state's cue (where it falls on the deck's timeline, its transition, each motion as placed), and `--data` the rows each chart and table reads (PLAN 1.14). `inspect --boxes` gives each node's box at rest, with the map its `transform` draws it through, and `--at X,Y` what draws at a point, read back through that map, topmost first, in any `--format`, and in a text where a caret put there stands (`offset`, in characters): what a pointer edits (PLAN 2.29, 2.32, 2.51, ADR-0013). `--layers` lists a state's nodes as the editor's layers do, those locked marked (PLAN 2.95). `--targets NODE` says where a node may go: what holds it, its cell, and the tracks, slots, or order it takes. `--look NODE` gives a node's look as a state shows it, and `--onto A,B` the patch that pastes it on others (PLAN 2.58). `--snap HOW --to X,Y,W,H` lands a dropped box there, with the `place` patch that puts the node there, kept to the state with `--fork` (PLAN 2.30–2.31). `--arrange A,B,…` with `--by DX,DY`, `--align EDGE`, `--spread WAY`, or `--order HOW` arranges several children of one container at once: moved together, aligned, spread, or put in front or behind, one patch of `place` ops or of `choose` ops of `z` (PLAN 2.42, `scaena_ops::arrange`); `--before NODE` or `--after NODE` puts one just before or after another as `--layers` lists them, by `z`, or in a stack by its order, and into another container with it, and `--into NODE` into a container, each placed as that container places what it holds (`place` with `parent`, PLAN 2.50). `--choices NODE` says what an inspector offers for a node: each property it edits, the theme's names for it or what the schema allows, the value shown, and where it lives (PLAN 2.33); a chart's or a table's source from the deck's, and each channel's field from the columns of its data that the channel can read (PLAN 2.41). `--state-choices` says the same of the state itself: its layout (the theme's layouts with a slot for each node placed in one), its transition, its hold, and its notes, which `set_state` writes (PLAN 2.36). `--layouts` suggests the layouts it may take, best first (by lint, then by the places the state would leave empty and the texts it would set in another role, `empty` and `recast`): each with the state laid out in it and linted in every format, and the `set_state` that gives it, those that draw it alike folded into one (PLAN 2.92, `scaena_ops::layouts`). `--inserts` says what an editor may insert: a text in each of the theme's roles, each shape, each image in the bundle, a chart and a table of each data source made from its columns (PLAN 2.41), and each shader preset, as `add_node` adds each (PLAN 2.34). Under `--json` every command prints exactly one JSON value on stdout, its result or `{ "error": { "exit", "message", "plan"? } }` (SPEC §7.1). `scaena render` renders states built from text, chart, table, shape (filled and stroked in colors or gradients), image (PNG or JPEG, SPEC §3.3), shader (every kind, from the node or a theme preset, SPEC §3.8), and container nodes (`stack`, `grid`, `frame`, `group`, laid out by `taffy`; a child names its container in `at.parent`, ADR-0008) to PNG, at rest or `--t` ms into the state's cue (its transition, eased or sprung, then its motions: presets, `anim` tracks, and choreography on one clock, SPEC §3.9), on the deck's canvas or, with `--format 9:16`, laid out again in one of its `formats` with the theme's template set for it, each node with its own layout there where its `formats` gives one (SPEC §3.4, ADR-0020, deck format 0.13), with `--painter cpu` (the default) or, in a CLI built with `--features gpu`, `--painter gpu`. Between states, changed text morphs word by word, shapes point by point, shaders by their uniforms, and a group composites its members as one layer (PLAN 1.12); looks also tint paints toward a theme color and draw a shape's outline on. A node's `transform` (`scale`, then `skew`, then `rotate`, about its `anchor`, then `translate`) draws it at rest and between states, part by part, about its box: what a container holds turns with it, a group's layer turns as one, and a cue's looks move a node inside its own (PLAN 2.51, SPEC §3.3; `scaena_core::pose`). `lint` runs validation, the document rules, and the layout rules (overflow, collisions, contrast against what is painted behind the text, chart text included, chart text under 12 pt, charts squashed too small to read, shaders behind data, missing glyphs, fonts whose licenses forbid embedding them (W230, PLAN 2.14), lines, motion, narrative, and a layout's place for a picture or a figure a slide leaves empty, W304) in every format the deck lists. `lint --fix` applies the fixes lint has checked by laying the state out again (PLAN 1.15, SPEC §7.4–§7.5), and a text's contrast error (E110, E111) carries the theme color that reads against what lies behind it wherever the choice reaches (PLAN 2.82). `patch` applies JSON Patch and semantic ops (`add_node`, `rename_node`, `set_prop` in a state, `place`, `replace_text`, `list`, `choose`, `annotate`, `group`, `ungroup`, `add_state`, `set_state`, …), all or none. It refuses a patch that would make the deck invalid and reports the lint delta and the states it changes (PLAN 1.16, SPEC §7.3; `docs/schema/patch.schema.json`). A patch that names a node or a state the deck has not is refused with the id meant where one is near it ("did you mean `title`?"), else with the first few the deck has (lift-up 10-24b USE-5). `remove_slide` and `move_slide` take a slide's beat with it, `scaena start --claim` tells a new slide's claim in a beat of its own, and lint W429 finds a beat no slide tells yet and fixes nothing, so a spine written first keeps its story (dogfood 3). `scaena find TEXT` finds it in the deck's texts, in every state, each text once for each place it is written, and in each node's `alt`, each state's notes, each beat's claim and notes, and the words a chart or a table draws, and `--replace` replaces every match in one patch, a `replace_text` where each text lives and a `replace` of the rest where it is written; a value of the data, a cell or a value a highlight picks out, is found and kept, `kept` saying where and why (PLAN 2.47, 2.83). `scaena data BUNDLE SOURCE` shows a data source's rows as written, by index, with each cell its column does not read, and `--edits` sets cells, adds rows, and takes them away, all or none, each value checked by its column's type: one write of the source's file that keeps every other byte, or a patch of rows written inline, refused as a patch is (PLAN 2.55, SPEC §3.10, `scaena_core::data::edit`). `scaena icons WORDS` finds the icons that ship, Phosphor's 1,434 (MIT), by the words of their names, tags, and categories, each its path and the view it is drawn on, which `add_node` adds as a shape whose `view` keeps their room, so a row of them keeps one weight (deck format 0.20, PLAN 2.104;
